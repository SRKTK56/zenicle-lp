## 2.1 レビューで決めた規則（2026-09-16 /design-review）

- **薄塗り／ゴーストのボタンで文字をオレンジにしない。** `#FF8A00` は白系の地で 2.3:1 しか出ず AA 未達。文字はネイビー（`--text`）、オレンジは枠と矢印だけ
- **ファーストビューのオレンジ塗りは1本**（主CTA）。ヘッダーの登録ボタンは別階層として許容。CUP 等の告知ピルはアウトライン
- **見出しの行間は 1.15。** Tailwind の `text-4xl` `text-5xl` は `line-height:1` を持ち込み、`leading-*` を打ち消す（media 変種が後勝ち）ので CSS で固定している
- **和文見出しは意味の切れ目で `<br>` を固定し、`word-break: keep-all`。** 語中改行（「止まりや／すい」）を出さない
- **モバイルの一覧は4枚で切る。** 1列で全件流すとサービス説明（ABOUT）が 12,000px 先になる。「すべて見る」をボタンで置く
- **サムネイルは上寄せで切る**（`object-position: 50% 28%`）。21:9 の中央切り出しは人物の頭が欠ける
- **色帯は `band-2` / 白 / `bg` を交互に。** 同じ帯を隣接させない
- **ヒーローは `.reveal`（IntersectionObserver）に入れない。** IO が動かない環境で空白になる。CSS アニメ（`.hero-in`）で出す
- セクションラベルは `.72rem`（ワークスペース規定 0.7rem 以上）

## 3. チームコンソール（`(team)/team/console`）

### 3.1 テーマ
- `bg-zen-void` / `bg-zen-bgCard` / `bg-zen-bgOverlayDark` / `text-white` / `text-zinc-*` / `hover:bg-white/5` を**すべて `--c-*` トークンに置換**し、ライトテーマにする（公開ページと同じ地）
- サイドバー: 白地、選択中は `bg-orange-500/10 text-orange-600 font-bold`、それ以外は `--c-text-muted`
- ヘッダー: 白地・下罫線 `border-line`。「チームコンソール」の h1 はネイビー

### 3.2 情報設計 — ページの構造 = 編集の構造
困りごと: **「どこを編集すれば公開ページのどこに出るか」が分からない。**
対策は3つ。順に効く。

1. **サイドバーを公開ページのセクション名・順番と完全に一致させる**（下表）
2. **各編集画面の冒頭に「チームページの『○○』に表示されます」＋そのセクションのプレビュー画像（縮小スクショで可）**を置く
3. **公開ページにメンバー限定の「✎ 編集」導線**を出す（モック `team.html?edit=1` の青いチップ）。クリックで該当コンソール画面へ

### 3.3 ページ ↔ 編集画面 対応表（サイドバーの順番そのもの）

| # | 公開チームページのセクション | コンソールのメニュー名 | 編集項目 | 現在の置き場 |
|---|---|---|---|---|
| — | カバー画像・チーム名 | **ヘッダー** | iconUrl（21:9）、name | 設定「表示・公開」 |
| 01 | プロジェクト説明動画 | **プロジェクト** | pitchVideoUrl、goalAmount | 設定「プロジェクト」（新設済） |
| 応援 | 累計・目標・達成率・応援ボタン・シェア | （自動） | 表示のみ。目標額は「プロジェクト」で | — |
| 02 | 活動紹介・メッセージ | **活動紹介** | description、thanksMessage（#47 で teams/:id に追加） | 設定「表示・公開」／シーズン設定 |
| 03 | メンバー紹介 | **メンバー** | メンバー、役割、プロフィール（avatar/bio） | メンバー |
| 04 | エールの使い道 | **使い道（支出）** | fundUsage | 支出 |
| 05 | 応援してくれている人 | （自動） | 表示のみ | — |
| 06 | 活動レポート | **活動レポート（投稿）** | progressPosts、支援者限定 reports | 投稿／レポート |
| 末尾 | SNS リンク | **SNS** | webUrl / xUrl / instagramUrl / youtubeUrl / otherUrl | 設定「SNS」 |
| — | 公開設定・誓約 | **公開設定** | status、コンプライアンス | 設定「表示・公開」「コンプライアンス」 |

「（自動）」の項目もサイドバーに**読み取り専用で並べる**（「自動で表示されます」と書く）。編集できないことを隠すと、探し続けてしまう。

### 3.4 コンソールトップ（`/team/console`）
「やること」を上に、「数字」を下に。
- 上段: 未完了の設定をチェックリストで（動画URL未登録／目標額未設定／使い道の登録が0件／今週の投稿なし）。各行から該当画面へ
- 中段: 公開ページの縮小プレビュー（iframe で `/t/<id>` を表示。編集後すぐ確認できる）
- 下段: 累計・応援者数・シーズン残日数

#### 2026-09-15 実物（#51 反映後）へのフィードバック
- ✅ ライト化・サイドバーの一致・「自動」ラベル・「やること」チェックリスト・「公開ページを見る」は仕様どおり
- ❌ 下段の5枚のカード（メンバー一覧／メンバー表示／進捗投稿／レポート／設定）は**旧名称のままの二重導線**。削除（残すならサイドバーと完全一致の名称に）
- ❌ 「所属チーム」ブロックの**「参加先プログラムID」生入力欄**はトップに置かない。チーム切替はヘッダーのプルダウンで足りる。プログラム参加は「受付中プログラムから選ぶ」画面へ分離
- ❌ 数字（累計・応援者数・残日数）が無い。「やること」の直下に置く
- △ サイドバー末尾の「メンバー表示」「リワード」は区切り線＋「その他」で分ける
- △ 「やること」は動画・目標額の2件のみ。使い道0件／投稿なし も対象に

### 3.5 編集画面はチームページそのもの（方針転換・2026-09-15）
コンソールに「セクション別の編集画面」を持つ設計（§3.2〜3.3）は**やめる**。理由:
**応援者と同じ画面を見ながら編集するほうが、何が足りないか・どうすれば魅力的になるかにチーム自身が気づける**から。

- チーム管理者・メンバーでログインすると、`/t/[id]` に「編集モード」の切り替えが出る（モック `team.html?edit=1`）
- 編集モードでは各セクションの右上に「✎ 編集」。押すと**モーダル**でそのセクションの項目だけを編集（ページを離れない）。モーダル冒頭に必ず「チームページの『○○』に表示されます」
- **空欄のセクションは、応援者に見える位置に「＋ 追加」の枠**で出す（「＋ 説明動画を登録する」「＋ 使い道を登録する」…）。空欄を隠さないことが気づきの仕掛け
- 目標額は応援レール内に「＋ 目標額を設定する」
- コンソールに残すのは: トップ（やること・数字・承認状況）／活動レポートと使い道の**一覧管理**（並べ替え・削除）／メンバー招待／公開設定・誓約／リワード。**文言・画像・リンクの編集はすべてページ側**
- スマホでも同じ（モーダルは全幅のボトムシート）

#### 3.5.1 コンソールの導線は「チーム一覧 → チームページ → その場でモーダル編集」の一本（2026-09-16 確定）
モック: `console.html`（一覧）→ `team.html?team=<id>&edit=1`（管理者）／`&role=member`（メンバー）

1. **`/team/console` ＝ 自分のチーム一覧**。ログイン中のアカウントが**管理者またはメンバーになっているチームだけ**を並べる（サムネ・チーム名・参加プログラムとシーズン・役割バッジ・やること件数）。他人のチームは出さない。サイドバーもメニューも無し。「その他」（新しいチームを作る／支援者限定レポート／リワード／公開設定・誓約）は末尾にまとめる
2. **チームを選ぶとチームページ（`/t/[id]`）が開く**。上部バーは「← チーム一覧」「役割」「やること n」「未公開の変更 n 件」「公開を申請する」「公開ページを見る」だけ。チーム切替のプルダウンは置かない（一覧に戻って選ぶ）
3. **管理者はその場で編集、メンバーは閲覧のみ**（メンバーが編集できるのは自分のプロフィールだけ）。役割は `TeamMember.role` で判定。
   本人のプロフィール編集もページ上のメンバーカードの「✎」から行う。そのために公開ロスター（`GET /teams/:id` の members）に**本人判定フラグ（`isMe` のような boolean）を足す**（2026-09-17 決定。`userId` を露出させない）。実装までは `/team/console/member-profile` で代替
4. **「✎ 編集」を押すと、その項目だけの編集フォームがモーダルで開く**。ページ遷移しない。保存するとモーダルが閉じてページに反映（承認フロー §3.7 に乗る）。スマホでは全幅のボトムシート。Esc／背景クリックで閉じる
5. **やること**は「公開ページで空欄になっている項目」を自動集計（動画・目標額・活動紹介・メンバー・使い道・活動レポート・SNS・プログラム参加）。各行から該当セクションへジャンプ。埋まると消える
6. 既存の `/team/console/*`（settings 5画面・posts・reports・members・programs）は、**一覧管理が必要なもの（投稿・活動レポート・使い道・メンバー招待）だけ残し、それ以外はモーダルに吸収して削除**する（2026-09-17 訂正: 使い道 `fund` は §3.5 のとおり一覧管理として残す。#54 の実装どおり）

#### 3.5.2 参加プログラムをページ上で見せる・エントリーする
- カバー直下に「参加プログラム」ブロック。参加中のプログラム名＋開催中シーズン（例: ROUND2 参加中）をチップで表示。応援者にも見える
- 編集モードの**管理者**には「＋ プログラムにエントリー」。ドロワーで**受付中プログラム（`acceptingEntries = true`）から選び**、主催者へのメッセージを添えて申請。以後は主催者の承認待ち
- `/team/console/programs`（#51 で新設）はこのドロワーに吸収してよい

### 3.6 メンバー情報を管理者が編集できる
- 現状: メンバー本人だけが自分のプロフィール（表示名・アイコン・自己紹介・SNS）を編集できる
- 変更: **チームの管理者（`TeamMember.role = admin`）は全メンバーの表示名・アイコン・自己紹介・SNS リンクを編集できる**。編集モードの各メンバーカード右上の「✎」から（モック参照）
- API: `PATCH /teams/:teamId/members/:memberId/profile` を admin にも許可（本人 or admin）。監査用に `updatedByUserId` を残す
- 追記（2026-09-17 依頼）:
  - コンソールの「メンバー一覧」にも管理者向けの各行「✎ 編集」を置く（同じモーダル・同じ API）。メールで本人を判別できるのはコンソールだけのため
  - コンソールの一覧＝公開ページのプレビュー＋管理用情報（メール・役割・未設定の注意）。項目と順番は公開ページに揃える
  - 表示名の fallback: `TeamMember.displayName` → アカウント表示名 → ニックネーム → 「メンバー」。アイコンは頭文字、無ければ人型（「×」は使わない）
  - 「やること」に「メンバーの表示名が未設定（n 名）」を追加し 03 へジャンプ

### 3.7 公開には必ず運営の承認が要る（承認フロー）
チームが編集した内容は**保存しても公開されない**。ゼニくる運営の承認後に公開する。

| 状態 | 誰が | 何が起きる |
|---|---|---|
| 下書き | チーム | 「✎ 編集」→保存。公開ページは**前の内容のまま**。編集モードでは該当セクションに「未公開の変更」バッジ、上部バーに件数 |
| 承認待ち | チーム→運営 | 「公開を申請する」でまとめて申請。バッジが「承認待ち」に。申請中は追加の編集も下書きに積める |
| 承認／差し戻し | 運営 | 運営コンソールの審査キューで**変更前後の差分**を見て承認 or 差し戻し（理由つき）。承認で公開ページが更新される |

- 承認の単位は「申請1回＝変更セクションの束」。セクション単位で部分承認できると運営が楽（任意）
- 現状の `Team.status`（DRAFT / PENDING_REVIEW / PUBLISHED）は「ページの存在」の審査。これとは別に**「内容の変更」の審査**を持つ（`TeamPageRevision` のような下書き＋審査履歴）
- 運営側: 審査キュー（未処理件数・チーム名・申請日時・変更セクション）、差分表示、承認/差し戻し、通知（Discord or メール）
- チーム側: 状態が常に見える（未公開の変更 n 件／承認待ち／差し戻し理由）
- **運用（2026-09-17）**: 実装済み（#56 第1・第2段階、本番反映 `a28d73b`）だが `TEAM_PAGE_APPROVAL_REQUIRED` は**当面 off**（保存＝即公開、運営は事後確認）。CUP 期間中は即公開を優先する。on にする前に審査キュー `/ops/platform/page-reviews` の動作と通知（Discord）を確認する。承認者不在で on にするとチームがページを更新できなくなる

#### 3.7.1 設計の決定（2026-09-15・田村さんの論点3つへの回答）

**① 承認済みの内容をどこから読むか → 公開 API は「公開済みの値」だけを返す。下書きは別**
- `Team` の既存カラム（name / description / iconUrl / pitchVideoUrl / goalAmount / SNS …）を**「公開済み」の置き場のまま**にする。`GET /teams/:id`・`/public/team-explore` は今までどおりこれを読む → **LP（zenicle.jp）側の変更は不要**
- 下書きは `TeamPageDraft`（teamId ごとに1件、編集対象フィールドの JSON）に持つ。編集モードのページは**認証付き**で `GET /teams/:id/draft`（公開値に下書きを重ねたもの）を読む
- 「公開を申請する」で `TeamPageRevision`（申請時点の下書きスナップショット・申請者・状態・審査者・理由）を作る。承認で `Team` へコピー → 公開。差し戻しは下書きに残る
- 差分表示は「`Team` の現在値 vs `Revision` の値」で足りる

**② 未承認の画像 → 許容する（推奨どおり）**
- URL は推測不能な UUID で、承認前はどこからもリンクされない。実害はほぼ無く、実装が最も軽い
- 問題が出たら「承認まで非公開領域＋署名付き URL」に切り替える。その余地は残す

**③ 承認の範囲 → ページ本体だけ承認、投稿などは即時公開＋事後確認（推奨どおり）**

| 承認後に公開（`TeamPageDraft` 経由） | 即時公開（運営は事後確認） |
|---|---|
| ヘッダー（カバー画像・チーム名） | 活動レポート（進捗投稿） |
| プロジェクト説明動画・目標エール額 | エールの使い道 |
| 活動紹介・応援者へのメッセージ | メンバー**本人**によるプロフィール編集 |
| SNS・リンク | 支援者限定レポート（元々限定公開） |
| **管理者**によるメンバー情報の編集 | |

- 即時公開のものは運営コンソールの「最近の変更」フィードに流し、**ワンクリックで非公開化**できるようにする（事後確認の担保）
- 将来「すべて承認制」に寄せたくなった場合に備え、種別ごとの「承認要否」はコードの定数ではなく設定にしておく（任意）

### 3.8 プログラムにエントリーしなくてもチームを作れる（2026-09-16 依頼）

**目的**: チームを作る順番を「まずチーム → 必要になったらプログラムへエントリー」にする。CUP に出るかどうかに関係なく、チームページを育てられるようにする。

## 4.1 数値表示の規則（2026-09-15 追加・田村さん提案）

- `totalAmount` は「順位表を公開しているプログラム」のみの合算。順位表を隠しているプログラムにしか参加していないチームは `totalAmount = 0` のまま
- したがって **`totalAmount = 0` のときは達成率ブロック（目標額・％・進捗バー）ごと非表示**にする。0% と出すと誤解を生む
- LP（`index.html` のチームカード）とモック（`team.html`）も同じ規則に揃えた
- **LP のチームカードは参加プログラムのバッジをチーム名の上に置く**（2026-09-17。サムネイルへの重ねは「邪魔」で却下）。正式名の「：」「｜」より前を短縮名に、最大2件＋「+n」。薄い地のアウトラインピル、`app.zenicle.jp/p/<programId>` へのリンク
- **LP のチーム一覧の掲載順は累計エール額（`totalAmount`）の高い順**（2026-09-17 決定）。同額は応援者数（`supporterCount`）の多い順、それも同じならサーバー順。アプリのホームも同じ順にする場合は田村さんへ依頼
